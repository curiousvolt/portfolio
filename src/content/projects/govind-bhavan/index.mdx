## System Overview

The Govind Bhavan Portal is a centralized management system engineered to digitize residential operations and student administration for a multi-story university residence. The platform replaces paper-driven logs and ad-hoc communication with automated rebate processing, facility booking, and real-time operational transparency.

## Architecture

The system utilizes a decoupled client-server architecture designed for high availability, low-latency data access, and maintainable state boundaries.

- **Client Layer**: Built with React and bundled via Vite for optimized asset chunking and sub-second Hot Module Replacement (HMR). Global state is isolated across focused React Context providers (Authentication, Mess Rebates, Facilities) to prevent unnecessary re-render cycles.
- **API Service**: A RESTful Node.js and Express service layer handling request validation, business logic enforcement, and secure database interactions.
- **Data Persistence**: MongoDB managed through Mongoose, leveraging indexed document schemas for efficient lookups across student rosters, rebate claims, and facility registries.

## Core Implementations

### Role-Based Access Control

User authentication is implemented using signed JSON Web Tokens (JWT) stored in HTTP-only cookies to mitigate XSS exposure. A centralized authorization middleware inspects token claims to enforce granular role boundaries:

- **Student Scope**: Query personal profile records, submit rebate requests within active temporal windows, view dining schedules, and register for residential events.
- **Administrator Scope**: Review, approve, or reject student rebate submissions, manage residential room allocation matrices, post public notices, and export audit reports.

### Mess Rebate Calculation Engine

The rebate subsystem automates dining fee adjustments based on pre-defined institutional policies:

- Requests must satisfy strict temporal window constraints (minimum 48-hour advance notice).
- Continuous absence rules enforce automatic minimum and maximum day limits per academic term.
- Concurrent rebate requests within overlapping date intervals are rejected via server-side schema constraints.

### Data Export and Administrative Tools

To assist accounting and audit workflows, the administrative interface includes a custom serialization pipeline:

- Generates structured CSV summaries of approved dining rebates and facility reservations.
- Leverages client-side blob streaming to process multi-megabyte datasets without blocking the main browser thread.
- Enforces strict input validation on all export query parameters to ensure date-bounded queries hit appropriate MongoDB compound indexes.

## Technology Stack

- **Frontend**: React, TypeScript, Vite, Tailwind CSS, Lucide Icons
- **Backend**: Node.js, Express, Zod (runtime request validation)
- **Database**: MongoDB with Mongoose ODM
- **Authentication**: JWT, bcryptjs password hashing
